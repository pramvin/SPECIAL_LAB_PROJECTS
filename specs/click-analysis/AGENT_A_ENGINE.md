## Build

1. `agents/schema.py`: add `stock_analysis` (DDL in SPEC) and `ensure(conn)` creating it. Stop creating the old tables (`agent_runs`, `agent_messages`, `agent_decisions`) unless the new code still logs per-call messages; if you want a per-call log, keep `agent_messages` linked by a new `analysis_id` column in a **new** table `stock_analysis_messages (analysis_id, role, output_json, error, tokens_in, tokens_out, latency_ms, created_at)` instead of reusing old ones.
2. `agents/analyze.py` (new): `run_analysis(conn_factory, llm, ticker, horizon="1w", fetchers=None) -> int` returns the `stock_analysis.id`. Steps: insert a `running` row → `news_live.refresh_ticker` (guarded, see SPEC) → `context.collect` (reuse it; skip the fundamentals, SEC, and macro fetchers: pass fetchers that return an "unavailable/skipped" result for them so no network call is made) → run the `market`, `news`, `social` roles in **3 parallel threads** using the existing validated call path (retries, number guard, evidence ids) → build `result` as in SPEC (counts, positive_share, items, sentiment from code; support/resistance from computed levels) → update the row (`ok` / `partial` / `error`, tokens, finished_at). Each thread uses its own DB connection (SQLite connections are not shared across threads; use `app.dbcompat.connect`). The whole function never raises: any failure ends in an `error` row with a short message (never include a key or URL with a secret).
3. Prompts: rewrite the `market` prompt so the model picks support and resistance **from the computed levels** and gives momentum and volume labels as in SPEC; shorten the `news` and `social` prompts to ask only for `direction` and `summary` (+ per-item sentiment for social). Plain English, 2 to 3 sentences, no jargon, no advice words like "buy" or "sell". Keep the number guard and the "no invented numbers" rule.
4. `app/analysis_api.py`: `router` with `POST` and `GET /api/analysis/{ticker}` exactly as in SPEC, including reuse rule, the one-running-per-ticker rule, the global `BoundedSemaphore(3)`, and background thread start (`threading.Thread(daemon=True)`). The thread builds its LLM from `agents.config` the same way the old `agents.run` did (`_make_llm`). Env var `AGENT_FAKE_LLM=1` makes the API use `FakeLLM` (for the orchestrator's local browser test).
5. CLI `agents/run.py`: replace with a tiny `python -m agents.run --tickers DIS,AAPL --horizon 1w [--fake]` that runs `run_analysis` and prints status and tokens. `--fake` refuses to run without `PLANWISE_DB` (keep that guard).
